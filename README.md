# 3D Model Soft

Навчальний проєкт реконструкції 3D з фото. План і розподіл завдань —
у [project_plan.md](project_plan.md).

## Модель камери

`services/camera_math.py` реалізує `extrinsics(camera)` та
`project(points_3d, camera) -> pixels` на NumPy.

- Камера дивиться на початок координат; вісь світу +Y спрямована вгору.
- Кути задано у градусах: азимут 0° відповідає позиції на +Z, 90° — на +X;
  elevation задає підняття до +Y у межах [-90°, 90°].
- `distance` — додатна відстань до початку координат у одиницях сцени.
- `fov_deg` — вертикальний кут огляду; пікселі квадратні.
- Координати зображення: u вправо, v вниз. Центри пікселів мають цілі
  координати; оптичний центр — `((width - 1) / 2, (height - 1) / 2)`.
- `R, t` переводять світову точку у координати камери: `R @ point + t`.
  Глибина додатна перед камерою. На полюсах азимут визначає поворот кадру.
- `project` приймає скінченний масив `(N, 3)` і повертає `(N, 2)`.
  Точки на площині камери або за нею отримують `NaN`; координати поза
  зображенням не обрізаються. Перед читанням маски перевіряйте скінченність
  координат і межі зображення.

Формула: `u = f*x/z + cx`, `v = f*y/z + cy`, де
`f = height / (2*tan(fov_deg/2))`, а x, y, z — координати камери.

Наявна папка пакета називається `3d_model_soft`. Через цифру на початку
імені для прямого імпорту використовується `importlib.import_module`;
всередині пакета — відносні імпорти.

## Перевірка

Тести не потребують нових залежностей, крім наявного NumPy:

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Покрито відомі проєкції, азимут і підняття, полюси, перспективу,
прямокутний кадр, некоректні параметри та невидимі точки.

## Синтетичні дані

```powershell
.venv\Scripts\python.exe scripts/generate_synthetic.py data/synthetic/ellipsoid
.venv\Scripts\python.exe scripts/generate_synthetic.py data/synthetic/sphere --radii 0.65 0.65 0.65
```

Генератор обчислює точні перетини променів з еліпсоїдом, центрованим у
початку координат. Три радіуси відповідають осям X, Y, Z. Маски бінарні,
без згладжування, обчислені в центрах пікселів. Наявна вихідна папка
не перезаписується. Дані зберігаються локально та ігноруються git.

Вихідна папка містить:

- `views/view_00.png` … `view_05.png`: RGBA, силует у каналі alpha (0 або 255).
- `views/cameras.json`: тестовий словник `ім'я PNG -> {azimuth, elevation,
  distance, fov}`; це локальний формат fixture. Остаточну структуру
  production-файлу має узгодити реалізація `views_repository` Студента 2.
- `ground_truth.npz`: точна `occupancy` у порядку осей XYZ, одновимірні
  координати центрів `x`, `y`, `z`, крок `spacing` і `radii`. Сітка включає
  запас навколо об'єкта. Її можна використати для IoU після space carving.
- `dataset.json`: параметри, конвенції та джерело кутів.

Профіль `--version v1.2` (типово) використовує азимути
30°, 90°, 150°, 210°, 270°, 330° та почергові підняття 20°/-10°.
`--version v1.1` використовує підняття 30°/-20°.
Джерело: [офіційний Zero123++ README](https://github.com/SUDO-AI-3D/zero123plus).
Збігаються кути; відстань 4 та вертикальний FOV 30° є параметрами
синтетичної сцени, а не заявленою калібровкою генеративної моделі.
Нульовий азимут вважається напрямком вхідного фото.

`--size` задає розмір квадратного кадру, `--resolution` — кількість
вокселів на вісь (типово 256 і 64). Великі радіуси можуть обрізати
об'єкт краями кадру. Колір об'єкта сталий і призначений для тестів
геометрії; текстурування на цих даних ще не оцінюємо.

## Space carving

`services/carving.py` надає `create_grid(bounds_min, bounds_max, resolution)`
і `carve(views, grid, chunk_size=65536) -> VoxelGrid`.
`resolution` — число для кубічної сітки або трійка розмірів XYZ.
Межі задають зовнішні кути об'єму; `origin` — мінімальний кут,
`spacing` — розмір комірки по кожній осі. Координати центра комірки:
`origin + (index + 0.5) * spacing`.

Кожен `View(camera, mask)` містить булеву маску `(height, width)`.
Для PNG спочатку отримайте маску з alpha: `rgba[..., 3] > 0`.
Алгоритм проєктує центри зайнятих вокселів і залишає лише ті,
які належать силуету **на всіх** ракурсах. Маска читається як `[v, u]`,
найближчий піксель визначається через `floor(pixel + 0.5)`.
Поза межами кадру `[-0.5, width-0.5) × [-0.5, height-0.5)` і за камерою
вокселі відкидаються. Вхідна сітка й маски не змінюються.
Розрахунки виконуються векторизовано порціями; `chunk_size` обмежує
тимчасові масиви координат, а сама occupancy зберігається повністю.

```python
import importlib

models = importlib.import_module("3d_model_soft.domain.models")
carving = importlib.import_module("3d_model_soft.services.carving")
synthetic = importlib.import_module("3d_model_soft.services.synthetic")

views = [models.View(cam, synthetic.ellipsoid_mask(cam))
         for cam in synthetic.zero123_cameras()]
grid = carving.create_grid(resolution=64)
result = carving.carve(views, grid)
# result.occupancy: bool[64, 64, 64], axes XYZ
```

Приклад виконується зі встановленим пакетом або `src` у Python path.
Відтворювана оцінка на синтетиці:

```powershell
.venv\Scripts\python.exe scripts/evaluate_carving.py
```

Для сітки 64³ та кадрів 256² отримано:

| Об'єкт | Кути | IoU | Recall |
| --- | --- | ---: | ---: |
| Сфера | v1.1 | 0.9512 | 0.9992 |
| Еліпсоїд | v1.1 | 0.9500 | 0.9984 |
| Сфера | v1.2 | 0.9528 | 0.9994 |
| Еліпсоїд | v1.2 | 0.9548 | 0.9982 |

IoU — перетин передбачених і справжніх зайнятих комірок, поділений на
їх об'єднання. Recall — частка справжніх зайнятих комірок, які збереглися.
Ці результати стосуються точних синтетичних силуетів та каліброваних камер.
Visual hull не відновлює невидимі в силуетах увігнутості; обмежені ракурси
залишають зайвий об'єм, а дискретні маски можуть втрачати граничні комірки.
Усі кадри мають охоплювати об'єкт. Стійкість до помилок масок за правилом
K із N — окреме наступне завдання.
