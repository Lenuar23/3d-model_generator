# Локальний інтерфейс Gradio

## Запуск у Docker

У корені проєкту виконайте:

```powershell
docker compose up --build
```

Відкрийте [інтерфейс](http://localhost:7860). Після підтвердження ракурсів
готова модель відкриється в інтерактивному 3D-переглядачі на сторінці.
Модель можна обертати, наближати та завантажити як GLB.

Compose підключає локальну папку `data/`. Для демонстрації завантажте фото
з `data/test_photos/` і залиште відповідні готові ракурси в
`data/task5_validation/`. Ці файли зберігаються локально. Контейнер
підтримує реконструкцію з готових ракурсів. Генерація ракурсів для нових
фото наразі використовує окреме Windows-середовище Zero123++ на NVIDIA GPU.

Готові ракурси підставляються лише за точного збігу вмісту завантаженого
файла з демо-фото. Статус у галереї вказує джерело ракурсів.
«Перегенерувати» запускає Zero123++ із новим seed. Якщо генерація
недоступна або завершується помилкою, попередні ракурси зберігаються.
Щоб порівняти якість із більшою кількістю кроків, перед запуском демо
у Windows задайте `$env:ZERO123_STEPS = "75"`. Типове значення — 28.

Для побудови інтерфейсу з переданими callbacks встановіть опційну групу
`ui`. Lock-файл фіксує Gradio 6.31.0. Ця група містить залежності інтерфейсу.

```powershell
uv sync --locked --extra ui
```

`build_app(generate, reconstruct=None)` приймає два сценарії застосунку.
`generate(photo: Path, seed: int) -> Path` повертає готову папку `views`
з шістьма PNG `view_00.png` … `view_05.png` та `cameras.json`.
Для кожного перегляду очікується RGBA PNG розміром 320 × 320.
`reconstruct(views_dir: Path) -> Path` за наявності повертає готовий файл GLB.

## Підключення сценаріїв

Передайте функцію генерації з [завдання 6](https://github.com/Lenuar23/3d-model_generator/tree/02d6e0f),
зв'язану з налаштованим `Zero123ViewGenerator` із
[завдання 5](https://github.com/Lenuar23/3d-model_generator/tree/b1a6d74).
Нижче `generator` — об'єкт, створений за інструкцією завдання 5.
У робочій копії мають бути файли обох завдань. Також можна передати
іншу реалізацію сценарію, яка виконує описаний файловий контракт.

Для інтегрованого запуску з `RembgRemover` після об'єднання гілок
завдань 5–7 встановіть обидві опційні групи. Група `background-removal`
визначена завданням 5 і встановлює CPU-залежності видалення тла.

```powershell
uv sync --locked --extra ui --extra background-removal
```

Сам Zero123++ потребує окремого середовища моделі з інструкції завдання 5.
Перед запуском підготуйте це середовище, його runner і ваги.

```python
from functools import partial
from importlib import import_module

def launch_ui(generator, reconstruct=None):
    scenario = import_module("3d_model_soft.app.generate_views")
    ui = import_module("3d_model_soft.ui.gradio_app")
    generate = partial(scenario.generate_views, generator=generator)
    app = ui.build_app(generate, reconstruct=reconstruct)
    app.launch(server_name="127.0.0.1", share=False, max_file_size="15mb")
```

Відкрийте адресу `http://127.0.0.1:7860`, якщо Gradio вибрав порт за
замовчуванням. Імпорт модуля та створення `Blocks` не запускають сервер.
Завантажені фото й окремі файли для перегляду обслуговує Gradio.
Для галереї PNG передаються як зображення в пам'яті. Для завантаження
моделі Gradio отримує копію лише перевіреного GLB.

## Робота з фото

1. Завантажте фото та натисніть **Згенерувати ракурси**.
2. Перегляньте шість кадрів і seed у полі стану.
3. **Перегенерувати** створює інший seed і замінює галерею після успішного запуску.
4. **Підтвердити** передає поточну папку `views` до `reconstruct` і показує
   готовий GLB для завантаження.

У поточній гілці реалізація реконструкції Студента 1 ще відсутня. Поки
сценарій не передано у `build_app`, кнопка підтвердження неактивна, а
поле стану пояснює причину. Після підключення сценарію підтвердження
працює з останньою успішною генерацією.

Заміна або видалення фото скидає галерею та попередній GLB. Початок
генерації скидає застарілі результати. При помилці можна повторити
генерацію, а діагностика залишається в журналі сервера. Стан окремий
для кожної сесії. Генерація, перегенерація та реконструкція проходять
через спільну чергу з одним робочим запитом, щоб уникнути одночасних
запусків моделі. Відповідь, що надійшла після зміни фото, відкидається.

[Gradio](https://pypi.org/project/gradio/6.31.0/),
[стан сесії](https://github.com/gradio-app/gradio/blob/gradio%406.31.0/gradio/components/state.py),
[параметри черги подій](https://github.com/gradio-app/gradio/blob/gradio%406.31.0/gradio/events.py).

## Перевірка

Тести перевіряють завантаження й скидання стану, шість прев'ю з
альфа-каналом, новий seed, відкидання застарілих відповідей і помилки.
Підтвердження тестується з підставленим callback, який отримує саме
останню папку `views`. Перевірка через `Blocks.process_api` використовує
справжній стан сесії та обробку виходів Gradio. Вона підтверджує, що
галерея й GLB доступні з кешу після очищення тимчасової копії GLB.

```powershell
uv run --extra ui python -m unittest discover -s tests -p test_gradio_app.py -v
```

Повний сценарій із реальною реконструкцією потребує реалізації Студента 1.
